# WebAE：在网页上查看 AE 网络

游戏内的 OC 电脑定时把 AE 网络的**能量、合成 CPU 状态、库存**上传到后端，你在浏览器里登录查看，也可以给**已经有样板的物品下单合成**、取消 CPU 上的合成任务。

```
OC 电脑（因特网卡 + 适配器接 ME） ──HTTPS──▶ 后端（你的电脑）◀── 浏览器
```

| 目录 | 内容 |
|---|---|
| `backend/` | Python 后端（FastAPI）和网页 |
| `oc/aeweb.lua` | 游戏内 OC 电脑运行的上传程序 |

## 一、启动后端（在你的电脑上）

1. 需要 [uv](https://docs.astral.sh/uv/)（已装）。进入 `backend/`：
   ```powershell
   cd D:\oc\ae-web\backend
   copy config.example.toml config.toml
   ```
2. 编辑 `config.toml`：
   - `oc_token`：OC 上传用的密钥。用 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 生成一串。
   - `web_password`：网页登录密码。
3. 启动：
   ```powershell
   uv run python app.py
   ```
   本机打开 <http://127.0.0.1:8765> 能看到登录页就说明后端正常。数据会保存在 `backend/data/state.json`，重启后不会丢。

## 二、让游戏服务器能访问到后端

后端只监听本机（`127.0.0.1`），需要一个内网穿透工具，提供一个公网 HTTPS 地址。

- **临时测试：Cloudflare 快速隧道**（不需要域名）
  ```powershell
  cloudflared tunnel --url http://127.0.0.1:8765
  ```
  它会打印出一个 `https://xxxx.trycloudflare.com` 地址。**每次重启 cloudflared 地址都会变**，OC 脚本里的地址也要跟着改。在国内访问不一定稳定。
- **长期使用**：任选一种
  - Cloudflare 命名隧道加上自己的域名，地址固定；
  - 国内的穿透服务（如 SakuraFrp）；
  - 以后迁移到 VPS。

  迁移时只需要复制 `backend/` 文件夹（包括 `config.toml` 和 `data/`），再改一下 OC 脚本里的地址。

先在浏览器里用这个公网地址能打开登录页，再继续下一步。

## 三、游戏内的 OC 电脑

**硬件**：
- 机箱和 CPU：T2 以上
- 内存：建议 2 根 T3.5
- 硬盘：装好 OpenOS
- 因特网卡
- 适配器：贴着 **ME 控制器**或**方块形式的 ME 接口**放，用线缆连到电脑。面板形式（贴在线缆上的薄片）的 ME 接口没有网络查询功能，不能用
- 合成 CPU 里要有**合成监控器**，网页上才能看到合成目标
- 区块必须一直加载：电脑所在区块卸载后程序就停了

**安装脚本**（后端提供了脚本下载）：
```
wget https://你的地址/oc/aeweb.lua /home/aeweb.lua
aeweb
```
第一次运行会生成配置文件 `/home/aeweb.cfg`，然后退出。编辑它：
```
edit /home/aeweb.cfg
```
填好两项（编辑器里 Ctrl+S 保存，Ctrl+W 退出）：
- `BASE_URL`：你的公网地址
- `TOKEN`：和 `config.toml` 里的 `oc_token` 完全一致

再运行 `aeweb`，正常情况下会打印：
```
[  237.2s] ae-web uploader started, target https://...
[  237.2s] memory: 1617 KB free of 2048 KB
[  244.9s] inventory: 3853 entries in 6.2s
```
用 **Ctrl+Alt+C** 停止。想开机自动运行，就执行 `echo aeweb >> /home/.shrc`。

**更新脚本**：只需要 `wget -f https://你的地址/oc/aeweb.lua /home/aeweb.lua`。配置在 `aeweb.cfg` 里，不会被覆盖。

想用别的配置文件，可以运行 `aeweb /路径/xxx.cfg`。

**可调参数**（在 `aeweb.cfg` 里取消注释再修改）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `STATUS_INTERVAL` | 5 | 能量和 CPU 的上报间隔（秒） |
| `ITEMS_INTERVAL` | 60 | 完整库存快照的间隔（秒）。扫描耗时较长时可以调大 |
| `CHUNK_LINES` | 500 | 库存上传时每个包的行数 |
| `CPU_ITEM_LIMIT` | 300 | 每个 CPU 的"现存 / 正在合成 / 计划合成"列表各最多上报多少条 |
| `CPU_CALL_BUDGET` | 60 | 每轮上报最多花多少次 AE 调用（约等于 tick 数）刷新忙碌 CPU 的详情，见下方说明 |
| `CPU_FINAL_REFRESH` | 60 | 忙碌 CPU 的合成目标多久重新读取一次（秒） |
| `HTTP_TIMEOUT` | 20 | 单次请求超时（秒） |
| `MAX_ITEM_ID` / `ID_BATCH` | 32767 / 512 | 库存扫描的物品 ID 上限 / 每批读取的 ID 数 |

**合成 CPU 详情的刷新方式**：OC 每调用一次 AE 接口，都要等服务端一个 tick。每轮上报都会读一次 CPU 列表，然后最多花 `CPU_CALL_BUDGET` 次调用，按"最久没刷新的优先"刷新忙碌 CPU 的详情（现存、正在合成、计划合成，每个 CPU 3 次调用）。空闲的 CPU 不读详情。
- 同时忙碌的 CPU 不多时，每轮全部刷新（5 秒）；
- CPU 很多时轮流刷新，比如 64 个同时忙碌时，每个 CPU 大约 15~20 秒刷新一次。

无论哪种情况，状态上报和下单都不会变慢。网页上每个 CPU 的详情旁边会显示"xx 秒前更新"。

## 四、网页上能看到什么

- **能量**：AE 储能、平均消耗、平均输入、待机消耗
- **合成 CPU**：布局和游戏内的合成监控器类似。
  - **左侧**：所有 CPU，显示合成目标、容量、协处理器数和已合成时间。
  - **右侧**：选中 CPU 的每种物品，显示"现存 / 正在合成 / 计划合成"的数量。正在合成的格子是绿色，计划合成的是黄色。可以搜索（支持拼音），也可以取消任务。
  - **已合成时间**：OC 不提供这个数据，是从后端**第一次看到 CPU 进入忙碌**时开始计时的，误差约一个上报间隔。如果开始时间没被观察到（比如后端重启时任务已经在跑），时间前面会标"≥"，表示实际时间更长。
  - **合成目标**：需要 CPU 里有合成监控器，没有时显示"目标未知"。游戏界面不需要监控器，OC 需要。
- **库存**：物品和流体，可以搜索中文名、拼音、英文名或注册名，按数量或名称排序，按"物品 / 流体 / 可合成"筛选，分页显示。
  - 拼音搜索和 JECH 一样：连续的几个字，每个字可以用它任意一个读音的前缀匹配，多音字的所有读音都算。所以"铁锭"可以用 `tieding`、`td`、`tied`、`铁d` 搜到。
- 页面顶部显示上一次状态上报和库存快照的时间。超时变黄或变红，说明 OC 程序可能停了。

## 五、汉化

服务端是英文的，OC 拿到的物品名也是英文。中文名来自客户端 NEI 的**物品面板导出**：用 `注册名:meta` 对应到中文名。

NEI 导出的是**物品面板当前显示的列表**，所以导出前要先做两件事：
- **清空 NEI 的搜索框**；
- **展开所有折叠的物品组**：点物品面板上的 **G** 按钮（提示为"Collapse/Expand All Collapsible Items"），或者在 NEI 选项里关闭"可折叠物品"。不展开的话，羊毛、树苗、GT 的同类物品等每组只会导出第一个。

1. **导出中文版**（客户端语言为简体中文时）：
   - 打开背包，点 NEI 左下角的**选项**；
   - 进入 **工具（Tools）→ 数据导出（Data Dumps）**；
   - 把 **物品面板（Item Panel）** 一行的模式切换到 **CSV**，点 **导出（Dump）**；
   - 生成的文件在游戏目录的 `dumps/itempanel.csv`。把它复制到 `backend/data/i18n/`，**重命名为 `itempanel_zh.csv`**。
2. **导出英文版**（可选，但**流体汉化必须要它**）：
   - 把游戏语言切换成 English (US)，按同样的步骤再导出一次；
   - 复制到同一个目录，**重命名为 `itempanel_en.csv`**；
   - 再把游戏语言切回中文。

   两次导出都写到同一个 `itempanel.csv`，所以每导出一次就要先把它复制走、改好名字。

后端会自动发现文件变化并重新加载，不用重启。库存标题后面会显示"汉化 N 条（含中英对照 M 条）"。

匹配规则，按顺序：
1. 按 `注册名:meta` 匹配；
2. 同一个 meta 有多个 NBT 变体（名字不同）时，按英文名查中英对照表；
3. 只有一个 meta 的物品（工具、装备，它们的 meta 是耐久值），用这一条的名字；
4. GTNH 在 NEI 里隐藏了 GT 的小撮粉、小堆粉、含杂粉、纯净粉，以及粉碎、洗净、离心矿石。这些物品按材料名推导中文名，例如"小撮碳粉""粉碎的金矿石"。推导模板是从 GT++、BartWorks 里同类未隐藏物品的中文名中总结出来的。
   - 小撮、小堆：和真实名称 100% 一致；
   - 粉碎、洗净、离心：约 70%~90% 一致，不一致的多是"的"字和"矿矿石"这类写法差异，原始翻译本身就不统一；
   - 含杂、纯净：没有可以对照的样本，是参照 GT++ 的命名推出来的。
5. 都匹配不到时，显示英文原名。

**更新整合包或加了 mod 以后，重新导出一次。**

## 六、下单合成

库存里标着蓝色"可合成"的物品或流体，也就是 ME 网络里有样板的，点一下就会弹出下单窗口：
- 填数量：可以直接输入，也可以用 ±1/10/100/1000 按钮调整。流体的单位是 L（mB），默认 1000 L；
- 选合成 CPU：自动，或者指定一个有名字的 CPU；
- 点**开始合成**。

订单会出现在"订单"列表里，状态依次是：排队中 → 已发送 → 计算中 → 合成中 → 完成。如果失败，会显示原因，比如"材料不足"。

合成中的 CPU 卡片上有**取消任务**按钮，作用和游戏内合成状态界面里的取消一样。

和游戏内的区别：OC 接口**没有"预览合成计划"的功能**。提交后 AE 会直接计算，缺材料就直接失败，不会像游戏里那样先列出缺什么。

工作方式和安全措施：
- 网页下单后，指令先放进后端队列。OC 每次上报状态（默认 5 秒一次）时把指令领走，结果在下一次上报时带回。
- 每条指令只会执行一次。OC 在调用下单接口**之前**，会先把指令 ID 记进 `/home/aeweb.handled`。即使网络重发或 OC 重启，同一条指令也不会执行第二次。
- 指令在队列里**超过 5 分钟没被领走就作废**，避免 OC 掉线很久之后突然执行一堆旧订单。还没被领走的订单可以**撤回**。
- OC 超过 1 分钟没有上报时，网页拒绝下单。
- 单次下单数量上限：物品由 `config.toml` 里的 `max_order_amount` 决定（默认 100 万个），流体由 `max_order_fluid_amount` 决定（默认 1000 万 L）。物品一次 1 万个以上、流体一次 100 万 L 以上时会二次确认。
- 流体样板通过 OC 的 `getCraftable({name=...}, "fluid")` 查找。如果找不到，会退回到按名字筛选全部样板。
- OC 程序重启后，正在跟踪的订单会变成"状态未知"，需要到游戏里确认。合成任务本身不受影响。

## 七、物品图标

图标来自 NEI 物品面板的 **PNG 导出**，用的是游戏自己的渲染，资源包、GT 染色、方块的 3D 外观都和游戏里一致。

1. 准备：游戏语言为中文，NEI 搜索框清空，点 **G** 展开所有折叠组。
2. 在 **选项 → 工具 → 数据导出 → 物品面板**：
   - 先用 **CSV** 模式导出一次；
   - **不要动物品面板**，马上切到 **PNG** 模式，选 **32x**，再导出一次。5 万多个物品需要渲染几分钟，期间游戏会卡住。
3. 导入（游戏目录下的 `dumps` 文件夹）：
   ```powershell
   cd D:\oc\ae-web\backend
   uv run python import_icons.py "D:\minecraft\GT_New_Horizons_2.9.0\.minecraft\versions\GT New Horizons 2.9.0\dumps"
   ```
   图标会复制到 `data/icons/<版本号>/`，大约 110 MB。重新导入时会替换旧版本，后端自动加载，不用重启。

NEI 是按**显示名**给图片命名的，所以导入脚本按 CSV 的顺序重放 NEI 的命名规则，把每张图对应回 `注册名:meta`。这也是 CSV 和 PNG 必须连续导出、中间不能动面板的原因。少数会随机改名的物品（比如 QED），按文本相似度配对。

匹配规则：
- 先按 `注册名:meta`；有多个 NBT 变体时用中文名区分；
- meta 表示耐久或电量的物品（氧气罐、权杖等），在同一个物品下按中文名找；
- 流体通过 NEI 的流体显示物品，按中文名找；
- NEI 里隐藏的 GT 小撮、小堆、含杂、纯净粉，借用同材料"粉"的图标，外观相近但不完全一样；
- 都找不到的（主要是 GT 粉碎矿石）显示灰色占位方块。

图标地址带版本号，设置了一年的浏览器缓存，Cloudflare 也会缓存。图标不需要登录就能访问，因为里面没有任何私密信息。

## 已知限制

- 物品数量取自 AE 转出来的物品堆。**超过约 21 亿的数量可能被截断**，还需要实测确认。流体不受影响。
- 只能指定**有名字**的合成 CPU。没命名的 CPU 只能通过"自动选择"使用；如果想指定，先在铁砧里给一个合成存储器或合成单元改名，再把它放进 CPU 结构里。CPU 会使用这个名字。
- 库存按**物品数字 ID 分批**读取（`getItemsInNetworkById`，默认每批 512 个 ID，扫描 0~32767）。每批都会让 AE 生成一次物品列表，网络非常大时可以把 `ITEMS_INTERVAL` 调大。
  - **不要改用 OC 的 `allItems()`**。它的迭代器会注册为 AE 的变化监听，在 AE 处理物品变动的过程中重建整个物品列表，会破坏 AE 内部的数据结构，导致服务器崩溃（`ArrayIndexOutOfBoundsException` at `ItemList.putItemRecord`）。早期版本用的就是它，已经出过一次事故。
  - 一批数据太大、内存放不下时，会自动对半拆开重试。如果单个 ID 下的物品都放不下，就跳过这个 ID，日志里会写 `skipped item IDs`。遇到这种情况，可以把服务端 `config/OpenComputers.cfg` 里的 `allowItemStackNBTTags` 改成 `false`，让物品数据不再附带 NBT。
- 汉化只覆盖 NEI 里能看到的物品。NEI 中隐藏的物品，以及没有对应英文名的 NBT 变体，会显示英文原名。按名称排序时按字符编码排序，不是按拼音。

## 安全

- `oc_token` 写在游戏里那台 OC 电脑上，能打开这台电脑的人都看得到。给电脑上锁，或者放在别人进不去的地方。
- 网页只有一个密码，**登录后就能下单**。分享给别人之前，至少换一个强密码。多用户和权限控制会在后续版本加入。
